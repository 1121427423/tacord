# 05 · 参数冻结表（Frozen Parameters v1 · 掩体切片 v1.3）

> **这份文档的目的**：在写第一行代码之前，把所有**跨系统的、后期改动代价高的**常量一次性定死。
> 凡是这里写了值的地方，实现时直接引用，不允许在代码里另起一套魔数。
> 单一数据源：`sim/data/constants.ron`（本文档是它的可读说明；CI 校验两者一致）。

## 0. 变更代价分级与变更流程

| 等级 | 含义 | 例子 | 变更流程 |
| --- | --- | --- | --- |
| **T0 架构级** | 改动 = 重写多个模块 / 数据格式全部失效 | 坐标定标、SIM_HZ、柱分辨率、地图尺寸、确定性策略、网络模型、单位硬上限、格式版本号 | 只能在 **M0 结束前**改；之后改动需重写受影响的整个子系统 + 全量回放回归 + 本文档与 `constants.ron` 同步 |
| **T1 结构级** | 改动 = 大改一个模块及其数据 | 编制（班 9 人）、掩体搜索半径、威胁场分辨率、装甲分区数、情报条目数 | 需评审 + 更新本文档 + 跑受影响指标（§90.3） |
| **T2 可调级** | 数据驱动、热重载、随时改 | 伤害、弹速、权重、时间常数、建造成本、概率阈值 | 直接改 `.ron`，记录到调参日志；要求能回答"它改变了 §90.3 里哪个指标" |

**铁律**：
1. 代码里出现任何"物理/玩法常量"字面量 = CI 失败（grep 白名单外的数字字面量）。
2. 新增跨系统常量 → 必须同时改本文档与 `constants.ron`，并标注等级。
3. T0 参数只允许在 `sim/src/constants.rs`（由 build script 从 `constants.ron` 生成）里定义，运行时**不可变**。

## 1. 世界与几何（T0）

| 常量 | 值 | 理由 |
| --- | --- | --- |
| `WORLD_SIZE_M` | **1024 m** × **1024 m** | 全 2 的幂：`1024 = 2^10`。配合 0.5m 柱 → 每轴 2048 = 2^11 柱；chunk 32 = 2^5 柱 → 每轴 64 = 2^6 chunk。索引/哈希全部可用位移，定点运算无除法。规模上足够容纳 8 座 FOB、补给线、侧翼包抄与 200 人交战 |
| `COLUMN_SIZE_MM` | **500 mm**（0.5 m） | 掩体粒度：能表达单扇窗、半个身位的墙垛、车与车的缝隙；再细（0.25m）内存翻 4 倍且掩体槽爆炸，再粗（1m）掩体过于方块化 |
| `GRID_DIM` | **2048 × 2048** 柱（4,194,304） | 由上面两项导出 |
| `CHUNK_DIM_CELLS` | **32**（= 16 m） | 重建/流式/并行分片单位；16m 是爆炸与建筑破坏的典型影响半径 |
| `CHUNK_GRID` | **64 × 64 = 4096** chunk | 导出 |
| `HEIGHT_MIN_MM / MAX_MM` | **−8000 mm … +48000 mm** | 下限给地道/地下室/河床，上限给 6 层楼 + 瞭望塔 |
| `MAX_SEGMENTS_PER_COLUMN` | **4** | 支持"一楼实体 + 窗户空洞 + 二楼楼板 + 屋顶"；4 段足够表达多层建筑，且可用 u8 索引 |
| 坐标系 | **Y-up，X 轴向东，Z 轴向南；方位角 0 = −Z（北），顺时针递增** | 与 Godot 约定一致（−Z 为前），角度方向必须冻结，否则三角函数与法线全部反号 |
| 世界边界 | 越界 = 不可通行软墙 + 视为敌对空旷地 | 防止寻路出界 |

**内存推导**：柱段 `{bottom_mm:i32, top_mm:i32, material:u16, hp:u16}` = 12 B；平均 1.3 段/柱 → 4.19M × 1.3 × 12 B ≈ **65 MB**（chunk 内 RLE 后可降到 ~30 MB）。在 §10.2.2 的 384 MB sim 预算内。

## 4. 士兵 AI 的实现方式（T0 —— 用户最关心的一条）

**结论：手写符号 AI。三层分层 + HTN 任务分解 + 效用评分做候选选择 + 分层状态机执行动作。不使用机器学习 / 神经网络 / LLM。**

| 备选方案 | 裁定 | 理由 |
| --- | --- | --- |
| 行为树（BT） | ❌ | 条件分支爆炸；无法表达"横向比较 12 个掩体候选"；tick 预算不可控；难解释 |
| GOAP / 规划器 | ❌ | 规划开销不可预测，无法保证 400 单位的预算；出问题难复现 |
| 机器学习 / 强化学习 / LLM | ❌ | **四条硬否决**：①不确定性（毁掉 lockstep 与回放）；②不可解释（玩家不知道他在干嘛）；③不可调参（改一个行为要重训）；④离线推理成本高。战术游戏要的是"可预测、可解释、可控" |
| **HTN + 效用 + HFSM** | ✅ | HTN 给出符合军事条令的行为骨架（可控、可读、可解释）；效用评分解决"选哪个"的横向比较（这是掩体系统的天然形态）；HFSM 执行动作（时间确定、可打断、可回放） |

### 三层结构与预算
| 层 | 频率 | 职责 | 每次预算（400 单位） |
| --- | --- | --- | --- |
| 指挥层 Commander | 1 Hz | 评估情报与兵力 → 给每个班派 Mission 与资源配额 | 2 ms（1 次/秒，含全部班） |
| 班组层 Squad | 2 Hz | 把 Mission 拆成 Role（火力组/突击组/压制/担架/工兵…），协调交替跃进 | 1.5 ms |
| 士兵层 Soldier | 10 Hz（决策）+ 每 tick（动作推进） | HTN 分解到原语动作；用效用评分选掩体/目标/路线 | 4 ms（含感知） |

**模拟 LOD 的依据（R1，T0 级约束）**：只能是 sim 内部状态（班组是否交战、距最近交战事件的距离、是否有任务）。
**相机位置、玩家选中、视锥、UI 焦点一律不得进入 sim** —— 否则不同玩家的镜头会让同一 tick 在不同客户端
走到不同状态，lockstep 必然分歧。相机只驱动渲染 LOD 与 UI。常量：`ai.lod_basis = "sim_state"`、
`ai.forbid_lod_inputs = [camera, selected, viewport, focus]`（CI grep 强制）。

**命中判定粒度（R3，T0）**：`ai.hit_granularity = "per_point"` —— 命中与"看得见"都走**逐采样点**射线，
汇总 `blocking_aggregate` 只用于掩体评分与探测速率，绝不作为命中门槛。

**每个决策必须输出 `Reason`（结构化调试串）**：`{layer, mission, role, action, candidates:[{id, score, top_factor}], chosen, rejected_because}`。这是可解释性 UI（§30.1.7）与 CI 回归（`sim_cli` 输出决策日志）的共同数据源。**没有 Reason 的决策不允许提交。**

### 个性与不确定性（T2）
`nerve / discipline / aggression / initiative / marksmanship / fitness / experience` 七维（§30.1.5），生成时按单位模板取样；**所有随机来自确定性 PRNG（PCG32），流 ID = `(level_seed, system_id, entity_id, tick)`**，保证并行顺序无关。

## 5. 确定性策略（T0 —— 已定，接口级冻结）

| 项 | 冻结内容 |
| --- | --- |
| **策略** | **方案 A：定点数**（bit-exact lockstep + 逐位一致的回放 + 可 bench） |
| 类型封装 | 位置/长度：`i32`（**毫米**）；角度：`u16`（0..65535 ≡ 0..2π）；标量：`Q16.16` 的 `i32`；概率：`u16` |
| 数学 | `sim_math` crate：查表三角（**4096 项 + 线性插值**）、定点 `sqrt/atan2/inv`、**不使用 libm** |
| 随机 | PCG32，按系统/实体/tick 分流，无全局共享状态 |
| **风险兜底（接口级冻结）** | 所有数值**只能**通过 `sim_math` 的抽象类型（`Mm`/`Ang`/`Q16`/`Prob`）访问，sim 内**禁止**裸 `f32/f64`（CI grep 强制）。这样即使 M0 末 go/no-go 判定改回浮点，**改动被限制在 `sim_math` 一个 crate 内**，sim_core 业务代码只改类型别名。这是"避免返工"的最后一道保险 |
| Go/No-Go | M0 第 2 周末：400 单位 bench + 三平台校验和一致 → 通过；否则切方案 B（浮点 + 服务器权威），代价是放弃 lockstep 与 bit-exact 回放 |

## 6.1 导航（M0.3 引入，T1）

> 表示方式在 §10.5.2 冻结：**地表 = 2D 代价场 + flow field**；多层室内与地道 = 显式图（M1+）。
> 本节只冻结地表这一层的参数。

| 常量 | 值 | 等级 | 备注 |
| --- | --- | --- | --- |
| 可行走高度 | 每柱**一个**值 = 该柱**最高可站立顶面** | T1 | 只存一个高度 ⇒ 桥下与桥面不能共存于同一柱，桥下走显式图 |
| 站立净空 `clearance_mm` | **1900 mm**（站高 1800 + 100 余量） | T1 | 顶面以上 1.9 m 必须完全空（半开区间，见 `World::overlaps`） |
| 姿态高度 | 站 1800 / 蹲 1200 / 卧 500（头顶，mm） | T1 | 必须 > `cover.samples_*_mm` 的最大值（CI 校验） |
| 肩宽 | **800 mm** | T1 | 与 `cover.slot_capacity_mm` 是同一条约束，CI 校验两者相等 |
| `step_up_mm` | **400** | T1 | 能直接跨上（≈ 一级楼梯）；墙（3000）靠这条挡住，不是靠"墙柱不可站立" |
| `step_down_mm` | **700** | T1 | 能直接走下 |
| `max_slope_deg` | **30°** | T1 | 阶梯近似的美术约束（R4）：斜面用阶梯表达，不做 >30° 的行走斜面 |
| 流场重算周期 | **15 tick（2 Hz）**，班组层 | T1 | 必须是 30Hz 的整数分频（摊还桶无余数） |
| 流场半径 | **128 m** | T1 | 一个目标一个场；全图 2048² = 419 万柱的 Dijkstra 太贵 |
| 步代价 | 正交 10000 / 对角 14142（= √2） | T1 | Q16 口径；M2 的威胁场作为**附加代价**叠加进同一个 Dijkstra |
| 不可达 | `u32::MAX` | T1 | 与真实代价绝不冲突 |

**两条容易写错的地方（都是真的踩过/推演过的）**：

1. **墙柱不是"不可站立"，而是"站得上去但爬不上去"**。墙顶是实体顶面（能站），
   3000 mm 的高差远超 `step_up_mm` ⇒ `can_step` 返回 false。
   写成"墙柱不可站立"会把**被炸矮的墙**（顶面只剩 300 mm，本该能跨过去）一并排除掉 —— 破坏系统的手感就毁了。
2. **铁丝网不是站立面**（`Material::standable()` 要求三个 flag 全 true），所以带铁丝网的柱**不可通行**，
   而不是"站在铁丝网顶上走过去"。

## 6.2 M1 掩体切片（v1.3 新增）

> M1 被切成能独立验收的小块。本节冻结**第一块（掩体派生 + 找掩体）**的参数，
> 都是"写错了要大范围返工"的那类。实现见 `sim_core::cover`，验收见 `sim_cli cover`。

| 常量 / 决策 | 值 | 等级 | 备注 |

**本块明确不做（M2）**：掩体图、`escape_score`、`firesupport_score`、压制场、
任务牵引 `objective_pull`、班长 proximity —— `cover.rs` 里这些项**恒为 0**，并在注释中标明。

**射线预算（M1 实际规模）**：默认 `scale.default_per_side = 32`（双方合计 64 人），
64 × (24 + 12) × 5 Hz ≈ 11.5k 射线/秒 × 0.86 µs ≈ **0.33 ms/tick**（掩体预算 2.0 ms）。
400 人的压力场景由 §15 的 LOD 分频兜住 —— 只有交战中的单位跑 Full LOD。

**§20.1.8 反脚本化验收的隐含前提（必须写清楚，否则测试会莫名其妙失败）**：

"3 秒内 blocking ≥ 0.7"这条，**物理上限是 9 m**（冲刺 3 m/s × 3 s，且这是直线距离，
实际要沿流场绕开建筑，路程通常是 1.5～2 倍）。所以：

- 验收场景的**掩体密度是验收的一部分**：出生点最近掩体 > 9 m 的样本，
  任何算法都不可能在 3 秒内达标（实测：这类样本占 7% 时成功率就是 93%）。
- `sim_cli cover` 会把"失败样本出生点到最近掩体的距离"打出来 —— 
  这个数字小，说明是**评分/移动**的问题；这个数字 ≥ 10 m，说明是**场景太空**。
  两者不能混为一谈（调试时在这里绕了很久）。

**两条必须记住的实现约束**：

1. **反脚本化**：槽位只由 `World` 的段 + `HeightField` 的可站立面决定，
   代码里没有、也不允许有"这里是掩体"的数据。`sim_cli cover` 用随机场景断言
   "3 秒内 blocking ≥ 0.7 的成功率 ≥ 95%"（§20.1.8）。
2. **"被挡住了吗"只走 `ray::blocked`**（R3）：掩体评分、视线、弹道共用同一个函数，
   三者不可能出现规则分歧。验收一律调用生产函数（`blocking_at` / `angular_factor`），
   测试里**不得重述阈值**（R10）。

## 9. 伤员链路（T2，含 R5 状态机）

**状态机（R5，原设计把 `Dead` 与 `Critical` 同时写成"失血归零的结果"，这里定死）**：

```
Active ──HP≤0──▶ Downed ──bleed_timer 归零──▶ Critical ──30s 无 CPR / CPR 失败──▶ Dead(终态)
                   ▲  ▲                          │
                   │  └──── CPR 成功（bleed 重置 15s，vitality −30）────┘
                   └── Aid 成功（→ Active）
   另：HP≤0 且 vitality ≤ 0  →  直接 Dead（"运气用完"，跳过 Critical）
```

| 状态 | 可爬行 | 可开枪 | 可被拖 | 可被 Aid | 可被 CPR |
| --- | --- | --- | --- | --- | --- |
| `Downed` | ✅ 0.22 m/s | ✅（手枪 ×0.35） | ✅ | ✅ | ❌ |
| `Critical` | ❌ | ❌ | ✅ | ❌ | ✅（仅医护兵 8s / 60%） |
| `Dead` | ❌ | ❌ | ✅（回收） | ❌ | ❌ |

**救援决策必须是 risk 的全函数**（R5，原设计在 `risk ∈ (0.45, 0.55]` 与"高风险但有掩护"处没有定义动作）：

| risk | 动作 |
| --- | --- |
| `[0, 0.45]` | 直接派 RESCUE（Runner + Cover man） |
| `(0.45, 0.55]` | 单兵低姿救援（走掩体链，不冲刺） |
| `(0.55, 0.85]` | 先 SUPPRESS 4–8s → 每 5s 重估：降下来就救 / 有掩体则 HOLD / 无掩体或进入 Critical 则强制救援 |
| `> 0.85` | 请求支援（烟雾/炮击/装甲）+ 持续压制 + 伤员自行爬行；**进入 Critical 时仍强制救援** |

## 19. 单一数据源与 CI 校验

```
sim/data/constants.ron   ← 人写（本文档的可执行镜像）
        │  build.rs（代码生成）
        ▼
sim_core/src/generated/constants.rs   ← 代码只用这个，编译期常量
        │
        ├─ CI: constants_hash 写入回放头（参数变了旧回放失效）
        ├─ CI: grep 检查代码里没有白名单外的数字字面量
        └─ CI: 校验 constants.ron 与本文档表格一致（tools/check_constants.py，解析 markdown 表与 ron 比对）
```

`tools/check_constants.py`（**已实现，38 项自检全部通过**）做四类检查，**任一失败即 CI 红**：

| 类别 | 检查内容 |
| --- | --- |
| A 派生量 | `grid_dim = size_mm / column_size_mm`、`chunk_grid = grid_dim / chunk_dim_cells`、四者均为 2 的幂 |
| B 时间分频 | 所有 AI 周期必须整除 `SIM_HZ`；快照周期为整秒；三种单局时长换算正确 |
| C 规模与预算 | 编制自洽（班 = 2×火力组+1 等）；柱数据内存估算 < sim 预算；tick p99 < tick 周期；威胁场网格整除世界尺寸 |
| D 文档 ↔ ron | 8 个 T0 常量（地图尺寸 / 频率 / 上限 / 编制 / 网络模型 / 输入延迟 / 定点策略 / AI 架构）在两处同时存在且一致 |

> 这套自检在第一次运行时就抓到一个真实错误：`size_mm` 被误写成 `1048576`（2²⁰ mm ≈ 1048.6 m），与文档的 1024 m 不符。这正是它存在的意义——**让机器拦住"文档与代码不同步"这个经典返工源**。
