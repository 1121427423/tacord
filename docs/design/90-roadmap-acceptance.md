# 90 · 里程碑、验收标准、风险与开放问题

## 90.1 团队假设与排期口径

> 排期按 **1–2 名全职开发者 + 美术外包** 估算；若团队规模变化，按"人月"线性换算。所有里程碑都以**可玩、可测、可演示**为完成标准，不以"代码写完"为标准。

## 90.3 量化验收标准（Definition of Done）

> 每条都必须是**可自动测量**（CI/headless）或**可重复人工测量**（带录像）的。测不了的进不了这个表。

### A 组 · 架构与平台（M0）
| # | 指标 | 阈值 |
| --- | --- | --- |
| A1 | 定点数学一致性 | 同一 seed 同一输入，在 Linux x86_64 / macOS arm64 / Windows 三平台跑 10 万 tick，状态校验和**逐位一致** |
| A2 | sim 性能（无渲染） | 400 单位 / 10 万 tick，p50 ≤ 6ms、p99 ≤ 11ms（M1 或同级别 CI 机器） |
| A3 | 内存 | 400 单位 + 1.6km² 世界，sim 常驻 ≤ 384 MB |
| A4 | 帧率 | M1 8GB / 1080p / 400 单位，p1 ≥ 55 fps（允许降级档位通过） |
| A5 | macOS arm64 构建 | CI 产出 ad-hoc 签名的 arm64 app，启动自检通过（30 秒无 ERROR） |
| A6 | 边界强制 | CI grep：`sim/` 无 godot 依赖、`godot/scripts/` 无规则逻辑 |
| A7 | 黄金回放 | ≥ 8 个回放用例三平台校验和一致 |

### B 组 · 掩体与单兵（M1）
| # | 指标 | 阈值 |
| --- | --- | --- |
| B1 | **无手工标记验证** | 1000 个程序化随机场景中，士兵在交火后 3 秒内进入 `blocking ≥ 0.7` 的掩体，成功率 ≥ 95% |
| B2 | 侧翼失效 | 敌人绕到 `coverage + 25°` 外后，1.5 秒内放弃该掩体，成功率 ≥ 90% |
| B3 | 掩体被毁 | 掩体被炸掉后 0.5 秒内该位置 `blocking < 0.2` |
| B4 | 姿态真实性 | 蹲下在矮墙后时，敌方的 `blocking(→该单位)` ≥ 0.95；起身开火时 ≤ 0.3（采样 100 次） |
| B5 | 命中一致性 | `blocking = 1.0` 时，射手对该单位的命中率 ≤ 1%（10 万次射击采样） |
| B6 | 压制生效 | 持续近失弹压制下，目标在 4 秒内进入 HESITANT，10 秒内进入 PINNED 的概率 ≥ 80% |
| B7 | 伤员链路 | 有可用队友时，`Downed` 单位 90 秒内被救回的概率 ≥ 70%；被拖行时仍开枪的次数 > 0（录像确认） |
| B8 | 弹药沉寂 | 一个班进入 RED/EMPTY 后，其火力输出在 60 秒内下降 ≥ 50% |

### C 组 · 班组与感知（M2）
| # | 指标 | 阈值 |
| --- | --- | --- |
| C1 | 记忆衰减 | 敌人消失后：3 秒内位置误差 ≤ 2m，12 秒内 ≤ 6m，45 秒后删除（1000 次采样） |
| C2 | 听声转向 | 未看见的枪声（80m，隔一堵墙）→ 单位在 1.2 秒内转向声源方向（±25°）的概率 ≥ 85% |
| C3 | 无线电共享 | 新 contact 在班组内传播到全班的平均延迟 ≤ 3 秒（含无线电延迟） |
| C4 | 杀伤区否决 | 路径上存在 `threat > 0.75` 且长度 > 15m 时，AI 自主选择不走的比例 ≥ 95%；玩家强制时单位进入 `reluctant` 并显示红色路径 |
| C5 | 手榴弹回掷 | 手榴弹落在 1.5m 内且引信 > 1.2s 时，回掷触发率 15–35%（不应过高也不应为 0） |
| C6 | 动作真实性 | 翻越/滑铲/扑倒/肉搏在 100 次触发中，动画与机制（暴露系数、位移、胜率）一致，无穿模、无卡死 |
| C7 | 可解释性 | 随机 50 次"玩家问：他为什么这么做"→ 面板能给出正确理由（人工核对）≥ 90% |

### D 组 · 基地与补给（M3）
| # | 指标 | 阈值 |
| --- | --- | --- |
| D1 | 建造亲手感 | 放下蓝图到建成期间，工人被打死 → 建造暂停（100% 确定性；录像确认） |
| D2 | 断供恶化 | 切断链路后，断点后 FOB 按 0/30/60/120/180 秒依次失去治疗/补弹/建造/补充/士气，误差 ≤ 5 秒 |
| D3 | 卡车伏击 | 敌方 AI 在"切断收益 > 攻击 FOB 收益"时选择伏击补给线的比例 ≥ 70%（构造场景测量） |
| D4 | 占领 | 占领条件与 AI/玩家完全一致；同规则 AI 对玩家 FOB 发起进攻的局数 ≥ 80%（10 局样本） |

### E 组 · 重装备与情报（M4）
| # | 指标 | 阈值 |

## 90.4 风险登记

| # | 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- | --- |
| R1 | **大规模 AI 的性能不达标**（掩体射线 + 感知在 400 单位下爆预算） | 高 | 中 | 分帧摊还、top-K 剪枝、缓存与事件失效、按 LOD 降级；M0 就做 400 单位 bench，不达标就先砍规模到 200（并调整设计目标） |
| R2 | **玩家看不懂 AI 在干什么** → 感觉"失控" | 高 | 高 | 可解释性 UI 是 M1 的硬需求（不是 M5 的打磨项）；任务分解可视化；语音气泡作为状态广播 |
| R3 | 定点数学改造成本超预期（D-2） | 中 | 中 | 退路方案 B（浮点 + 服务器权威），代价是放弃 lockstep 与 bit-exact 回放；在 M0 结束前必须做一次 go/no-go |
| R4 | `gdext` 绑定在某些 Godot 版本上出问题（D-1） | 中 | 中 | 绑定层保持极薄（≤ 2000 行）；退路：C ABI + C++ 薄包装；`sim_core` 永远不依赖引擎 |
| R5 | Godot Metal 后端在部分机型/驱动上有 bug | 中 | 中 | 启动探测 + 三级回退（Metal → MoltenVK → Compatibility）；崩溃两次自动降级并写日志；设置项允许手动覆盖 |
| R6 | 体素破坏导致掩体/导航/渲染三者不一致 | 高 | 中 | 三者都从同一份柱数据派生；破坏只走"修改柱 → chunk 标脏 → 局部重建"一条管线；属性测试用暴力采样做 oracle |
| R7 | 掩体评分调参无止境（"AI 总选奇怪的位置"） | 中 | 高 | 参数全部外置 + 热重载；`sim_cli dump` 可视化评分；建立"奇怪行为"样本库，每条对应一个回归用例 |
| R8 | Apple 公证 / 开发者账号 / 证书轮换 | 低 | 中 | ad-hoc 通道保底；CI 支持有/无证书两种模式；文档化证书注入流程 |
| R9 | 沙箱（Linux x86_64）无法验证 macOS 行为 | 中 | 高 | 所有逻辑在 Linux 上验证（sim/bench/回放）；macOS runner 只负责"能构建 + 能启动"；真机验证清单交给人工 QA（每周一次） |
| R10 | 手榴弹回掷 / 投降等"罕见事件"在测试里不出现 | 中 | 中 | 用 headless 批量跑（1000 局）统计频率；把概率参数外置以便回归校准 |
| R11 | 内容量（建筑/载具/动画）超出美术预算 | 中 | 高 | 低多边形 + 模块化套件 + 程序化变体；M1 只用 1 套建筑套件 + 2 种角色；动画用共享骨骼与程序化叠加 |

## 90.5 开放问题（需要拍板）

| # | 问题 | 选项 | 默认建议 |
| --- | --- | --- | --- |
| **D-1** | `sim_core` 用 Rust（`gdext`）还是 C++20（`godot-cpp`） | A. Rust（内存安全、rayon、无 GC） / B. C++20（生态成熟、团队更可能熟悉） | **A**（若团队不熟 Rust 改 B，成本约 +2 周且需更严格的内存纪律） |
| **D-2** | 定点（bit-exact lockstep）还是浮点（服务器权威） | A. 定点 / B. 浮点 | **A**（R1  mitigations 到位的前提下）；M0 末 go/no-go |
| **D-3** | 首张地图主题 | A. 沙漠城镇（与参考视频一致） / B. 东欧工业区 / C. 丛林 | **A**（美术资源最贴近参考素材，光照简单，利于早期性能） |
| **D-4** | 是否做"假投降"与"战争罪行开关" | A. 都做（默认开，概率低） / B. 都不做 | **A**（低概率假投降 5%；战争罪行开关默认关）——如发行/分级有顾虑则改 B |
| **D-5** | 医疗单位是否受保护 | A. 受保护（可被配置关闭） / B. 不受保护（更残酷） | **A**（机制上有意义，且是"绝不丢下任何人"的支柱支撑） |
| **D-6** | 首切片（M1）范围是否包含伤员系统 | A. 包含（推荐） / B. 先只做掩体与交战 | **A**（P5 是支柱，且它是"让人一眼看出这不是普通 RTS"的差异化点） |
| **D-7** | 相机是否支持"进入士兵视角" | A. 只读 cinematic 跟随 / B. 完全不支持 | **A**（低实现成本，高演示价值） |
| **D-8** | 是否做夜间/热成像 | A. 1.0 做夜间地图（不做热成像） / B. 都不做 | **A**（夜间大幅提升"听声辨位"与压制的玩法价值，成本低） |

## 90.6 参数总表索引（调参入口）

## 90.7 下一步（M0 第一周的具体动作）
