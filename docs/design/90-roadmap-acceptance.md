# 90 · 里程碑、验收标准、风险与开放问题

## 90.1 团队假设与排期口径

> 排期按 **1–2 名全职开发者 + 美术外包** 估算；若团队规模变化，按"人月"线性换算。所有里程碑都以**可玩、可测、可演示**为完成标准，不以"代码写完"为标准。

## 90.2 里程碑路线图

| 里程碑 | 周期 | 目标 | 可演示内容 | 完成判据 |
| --- | --- | --- | --- | --- |
| **M0 技术验证** | 2 周 | 打通"定点 sim + Godot + macOS arm64"骨架 | `sim_cli` 跑 400 单位在体素世界寻路；Godot 里 400 个小方块移动 | A 组通过；CI 三平台绿；**G1 门槛** |
| **M1 核心切片** | 6 周 | 掩体派生 + 单兵交战 + 伤员救援闭环（**含最小威胁评估 `threat_at()`**） | 200×200m 街区，2 个班对射：找掩体、探身开火、被压制、倒下、被拖回 | B 组通过；**G2 门槛**（外部试玩 + 可玩性评分） |
| **M2 小队与指挥** | 6 周 | 班组层、感知记忆、**完整 ThreatField**、动作集、手榴弹 | 交替跃进、包抄、听声转向、无线电报点、翻越/滑铲/扑倒、手榴弹回掷 | C 组通过 |
| **M3 打磨与 EA 准备** | 6 周 | 平衡、性能、可解释性 UI、教程、崩溃上报、macOS 公证 | 完整一局遭遇战（20–30 分钟） | D 组通过；**G3 门槛** |
| **── EA 发布 ──** | **约 20 周** | **见 §90.1.1 EA 范围** | 可购买可运行 | 崩溃率 < 1 次/小时 |
| M4 基地与补给（1.0） | 6 周 | FOB、建造、补给链、工事、占领、失败条件 | 建 FOB → 卡车被伏击 → 断供 → 阵地沉寂 | E 组通过 |
| M5 重装备与情报战（1.0） | 6 周 | 坦克、RPG 绕后、FPV、俘虏/审讯/倒戈、地道、医疗帐篷 | 坦克巷战 + 俘虏情报 + 担架队后送 | F 组通过 |
| M6 多人（1.0） | 6 周 | Lockstep、合作/对战 | 2 人在线对战一局 | G 组通过；**G4 门槛** |

> **R6 依赖修正**：伤员救援的风险评估原本依赖 M2 的完整 ThreatField，但救援和 B7 验收在 M1。
> 解决方案不是延后救援（那是支柱 P5），而是把**最小威胁评估提前**：
> - **M1 引入 `threat_at(pos)`**：按需计算（附近已知 contact 影响 + 最近 6 秒弹着密度），
>   不做全图场、不做寻路代价叠加。够用于"要不要派人去救"。
> - **M2 才有完整 ThreatField**（8m 栅格）+ 寻路代价叠加 + 杀伤区否决（C4 验收）。
> - 两者共用同一个函数签名 `threat_at(pos) -> Q16`，M1 版是 M2 版的无缓存退化实现，接口不变，不会返工。

### 90.1.1 范围与排期（R7：原计划与团队规模不匹配）

原计划"1–2 人 × 38 周 → 交付战役 + 两张地图 + 全部 P1–P6 + 在线合作与对战"是**不可信**的。
这里把首发范围收缩到"能验证核心差异的最小切片"，其余按 go/no-go 解锁：

| 内容 | EA（首发，≈20 周） | 1.0（解锁后追加 ≈18 周） |
| --- | --- | --- |
| 模式 | 单机遭遇战（Skirmish）vs AI | 战役关卡序列、在线合作、**在线对战 1v1** |
| 地图 | **1 张** 1024m 沙漠城镇（昼）+ 同一布局的夜战变体 | 第 2、3 张地图 |
| 阵营 | 1 套共用 AI 的双方（装备差异） | 叛军地道/牢房等阵营特色 |
| 掩体 / 感知 / 班组 AI / 伤员链路 | ✅ **核心差异，全部包含** | 打磨 |
| 弹药经济 / 压制 / 士气 | ✅ | 打磨 |
| 基地建造 / 补给链 / 工事 | ❌ | M4 |
| 坦克 / FPV / 俘虏审讯 / 医疗帐篷 | ❌ | M5 |
| 多人（lockstep） | ❌ | M6 |
| 可解释性 UI / 教程 / 本地化 | ✅（最小可用） | 完整 |

**核心差异 = 掩体来自真实几何 + 士兵自主求生 + 伤员链路。** 这三样在 EA 全有；
基地、坦克、俘虏是"同一套 AI 的更多舞台"，属于验证核心之后再解锁的内容，不做进首发默认范围。

### 90.1.2 Go/No-Go 门槛（每个门槛不通过就**停下修**，而不是继续推进）

| 门槛 | 时点 | 判据 | 不通过的处理 |
| --- | --- | --- | --- |
| **G0** | M0 第 2 周 | 定点 vs 浮点（D-2）技术可行性：400 单位 bench + 三平台校验和一致 | 切方案 B（浮点 + 服务器权威），放弃 lockstep |
| **G1** | M0 末 | A 组全通过；400 单位 p99 ≤ 11ms/tick | 把设计规模从 400 降到 200 单位，重算所有预算 |
| **G2** | M1 末 | B 组全通过 **且** 外部试玩 5 人可玩性 ≥ 5/7（"我理解士兵在干什么"） | 继续打磨 M1（可解释性 UI / 掩体权重），**不进 M2** |
| **G3** | M3 前 | M1 8GB 上 400 单位 60fps（p1 ≥ 55） | 砍 AI 频率或单位数，或提高最低配置到 M2 |
| **G4** | M6 前 | 联网（RTT ≤ 150ms）可玩，无频繁 stall | EA 只发单机，多人延到 1.0 之后 |

> 排期数字按 1–2 名全职 + 美术外包估算，团队规模变化时按"人月"线性换算。
> 不含美术外包等待时间；**每个里程碑以"可玩、可测、可演示"为完成标准，不以"代码写完"为标准**。

## 90.3 量化验收标准（Definition of Done）

> 每条都必须是**可自动测量**（CI/headless）或**可重复人工测量**（带录像）的。测不了的进不了这个表。

### A 组 · 架构与平台（M0）
| # | 指标 | 阈值 |
| --- | --- | --- |
| A1 | 定点数学一致性 | 同一 seed 同一输入，在 Linux x86_64 / macOS arm64 / Windows 三平台跑 10 万 tick，状态校验和**逐位一致** |
| A2 | sim 性能（无渲染） | 400 单位 / 10 万 tick，p50 ≤ 6ms、p99 ≤ 11ms（M1 或同级别 CI 机器） |
| A3 | 内存 | 400 单位 + 1024m×1024m 世界，sim 常驻 ≤ 384 MB（柱数据估算 ≈ 62 MB） |
| A4 | 帧率 | M1 8GB / 1080p / 400 单位，p1 ≥ 55 fps（允许降级档位通过） |
| A5 | macOS arm64 构建 | CI 产出 ad-hoc 签名的 arm64 app，启动自检通过（30 秒无 ERROR） |
| A6 | 边界强制 | CI grep：`sim/` 无 godot 依赖、`godot/scripts/` 无规则逻辑 |
| A7 | 黄金回放 | ≥ 8 个回放用例**三平台**（Linux / Windows / macOS arm64）校验和一致，由 artifact 比对 job 判定（R9） |
| A8 | **相机无关性**（R1） | 同一回放跑两遍，注入两条不同的相机轨迹 + 不同的选中集合（纯表现输入），逐 tick 校验和**完全相同** |
| A9 | 模拟 LOD 依据（R1） | 代码审查 + grep：`sim_core` 内不出现 `camera` / `selected` / `viewport`；模拟 LOD 只读 sim 状态 |
| A10 | 信息分层（R2） | sim 内无 fog 概念；迷雾只在渲染/UI 层按己方 contact 过滤；单测断言「未发现的敌人 sim 状态存在，但渲染层不产出」 |

### B 组 · 掩体与单兵（M1）
| # | 指标 | 阈值 |
| --- | --- | --- |
| B1 | **无手工标记验证** | 1000 个程序化随机场景中，士兵在交火后 3 秒内进入 `blocking ≥ 0.7` 的掩体，成功率 ≥ 95% |
| B2 | 侧翼失效（**直接调用生产函数**） | 敌人移动到使 `angular_factor(slot, threat) == 0` 的位置后，1.5 秒内放弃该掩体，成功率 ≥ 90%（测试 `use sim_core::cover::angular_factor`，不重述角度阈值 —— R10） |
| B3 | 掩体被毁 | 掩体被炸掉后 0.5 秒内该位置 `blocking < 0.2` |
| B4 | 姿态真实性 | 蹲下在矮墙后时，敌方的 `blocking(→该单位)` ≥ 0.95；起身开火时 ≤ 0.3（采样 100 次） |
| B5 | 命中一致性 | `blocking = 1.0` 时，射手对该单位的命中率 ≤ 1%（10 万次射击采样） |
| B6 | 压制生效 | 持续近失弹压制下，目标在 4 秒内进入 HESITANT，10 秒内进入 PINNED 的概率 ≥ 80% |
| B7 | 伤员链路（**口径已修正**） | **在 `risk ≤ 0.85`** 且班组有可用队友的条件下，`Downed` 单位 90 秒内被救回概率 ≥ 70%；`risk > 0.85` 场景单独统计，只要求「有明确动作」；被拖行时仍开枪次数 > 0（录像确认） |
| B9 | **逐点命中**（R3） | 只露头胸、躯干被墙挡住时：正面射击 10 万次，被遮挡部位命中率 ≤ 0.1%，命中全部落在暴露部位；同位置 `blocking_aggregate ≈ 0.7`（证明汇总值与逐点判定确实不同） |
| B10 | 伤员状态机（R5） | `Downed →(bleed 归零)→ Critical →(30s 无 CPR)→ Dead` 逐态可达；CPR 成功 → 回 `Downed`（bleed 重置 15s、vitality −30）；`vitality ≤ 0` 时倒下直接 `Dead`；`Dead` 为终态 |
| B11 | 救援决策完整性（R5） | `rescue_decision(risk, state, has_cover)` 对 risk ∈ [0,1] 步长 0.05 × 4 种状态组合**全部返回明确动作**，不得返回 `None` |
| B8 | 弹药沉寂 | 一个班进入 RED/EMPTY 后，其火力输出在 60 秒内下降 ≥ 50% |

## 90.4 风险登记

| # | 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- | --- |
| K1 | **大规模 AI 的性能不达标**（掩体射线 + 感知在 400 单位下爆预算） | 高 | 中 | 分帧摊还、top-K 剪枝、缓存与事件失效、按 LOD 降级；M0 就做 400 单位 bench，不达标就先砍规模到 200（并调整设计目标） |
| K2 | **玩家看不懂 AI 在干什么** → 感觉"失控" | 高 | 高 | 可解释性 UI 是 M1 的硬需求（不是 M5 的打磨项）；任务分解可视化；语音气泡作为状态广播 |
| K3 | 定点数学改造成本超预期（D-2） | 中 | 中 | 退路方案 B（浮点 + 服务器权威），代价是放弃 lockstep 与 bit-exact 回放；在 M0 结束前必须做一次 go/no-go |
| K4 | `gdext` 绑定在某些 Godot 版本上出问题（D-1） | 中 | 中 | 绑定层保持极薄（≤ 2000 行）；退路：C ABI + C++ 薄包装；`sim_core` 永远不依赖引擎 |
| K5 | Godot Metal 后端在部分机型/驱动上有 bug | 中 | 中 | 启动探测 + 三级回退（Metal → MoltenVK → Compatibility）；崩溃两次自动降级并写日志；设置项允许手动覆盖 |
| K6 | 体素破坏导致掩体/导航/渲染三者不一致 | 高 | 中 | 三者都从同一份柱数据派生；破坏只走"修改柱 → chunk 标脏 → 局部重建"一条管线；属性测试用暴力采样做 oracle |
| K7 | 掩体评分调参无止境（"AI 总选奇怪的位置"） | 中 | 高 | 参数全部外置 + 热重载；`sim_cli dump` 可视化评分；建立"奇怪行为"样本库，每条对应一个回归用例 |
| K8 | Apple 公证 / 开发者账号 / 证书轮换 | 低 | 中 | ad-hoc 通道保底；CI 支持有/无证书两种模式；文档化证书注入流程 |
| K9 | 沙箱（Linux x86_64）无法验证 macOS 行为 | 中 | 高 | 所有逻辑在 Linux 上验证（sim/bench/回放）；macOS runner 只负责"能构建 + 能启动"；真机验证清单交给人工 QA（每周一次） |
| K10 | 手榴弹回掷 / 投降等"罕见事件"在测试里不出现 | 中 | 中 | 用 headless 批量跑（1000 局）统计频率；把概率参数外置以便回归校准 |
