# 30 · 士兵 AI、战斗与表现

## 30.1 AI 决策架构：三层 + HTN + 效用

### 30.1.1 为什么是 HTN + 效用（而不是行为树或纯 GOAP）

| 候选 | 评估 |
| --- | --- |
| 行为树 | 条件分支爆炸，难以表达"找掩体"这种需要横向比较几十个候选的问题；难以解释 |
| 纯 GOAP | 表达力强，但规划开销与不可预测性高，调试痛苦，难以保证 tick 预算 |
| **HTN（层次任务网络）+ 效用评分** | 上层用 HTN 保证"大体行为可控、可读、可解释"（符合军事条令的结构），叶子节点用效用评分做"选哪个掩体 / 打哪个目标 / 走哪条路"的横向比较。可解释性好、预算可控、易于用个性参数扰动 |

### 30.1.2 三层结构

```
┌─ 指挥层（Commander AI，1 Hz）───────────────────────────────┐
│ 输入：已知敌情（情报）、己方兵力/弹药/补给、FOB 状态、任务目标    │
│ 输出：给每个班分配 Mission（ASSAULT / DEFEND / FLANK / SCREEN │
│       / RECON / BUILD / REPAIR / RESUPPLY / MEDIC / ESCORT   │
│       / AMBUSH_SUPPLY / WITHDRAW）+ 优先级与资源配额          │
└───────────────────────┬─────────────────────────────────────┘
┌─ 班组层（Squad AI，2 Hz）────────────────────────────────────┐
│ 把 Mission 拆成 Role：FIRE_TEAM / ASSAULT_TEAM / SUPPRESS    │
│ / MEDIC_TEAM / STRETCHER_TEAM / ESCORT / ENGINEER / SCOUT    │
│ 协调：交替跃进（bounding overwatch）、跃进时机与节奏、火力分配  │
│ 管理班组黑板：弹药存量、伤员列表、俘虏、共享 contact、士气      │
└───────────────────────┬─────────────────────────────────────┘
┌─ 士兵层（Soldier AI，5–10 Hz + 事件打断）────────────────────┐
│ HTN：任务 → 方法 → 原语动作（MoveToCover / PeekFire / Reload  │
│ / ThrowGrenade / Drag / Aid / Vault / Pickup / Surrender…）   │
│ 每个"选择点"用效用评分（掩体 §20.1.5、目标选择 §30.3.3）      │
└─────────────────────────────────────────────────────────────┘
```

**玩家的指挥命令走同一条链路**：玩家下达的是 Mission（不是"走这里"），班长同样会拆解成 Role 与原语动作。这保证 AI 与玩家同规则（P6），也让"任务分解可视化"成为 UI 的核心功能。

### 30.1.3 一个士兵的一 tick（伪代码）

```
fn soldier_tick(u, ctx) {
    // 1. 事件优先（不等摊还周期）
    if u.events.has(NEW_CONTACT | SHOT | COVER_FLANKED | ORDER_CHANGED | WOUNDED | GRENADE_NEARBY)
        || u.next_think_tick <= ctx.tick {
        u.next_think_tick = ctx.tick + think_interval(u.lod);   // Full: 3 tick / Reduced: 10 / Dormant: 60
        // 2. 重新选择"任务方法"（HTN 分解，缓存上次结果，失败才回溯）
        let plan = htn_plan(u, ctx);          // 返回原语序列或继续执行中的动作
        // 3. 执行动作（动作是状态机，内部有自身的 tick 逻辑）
        u.action.tick(u, ctx, &mut ctx.commands);
    } else {
        u.action.tick(u, ctx, &mut ctx.commands);   // 只推进当前动作
    }
}
```

### 30.1.4 交战循环（Fire Discipline）—— 支柱 P2 的落地

这是单个士兵最常见的行为序列，参数化后每个士兵略有不同（避免整齐划一）：

| 掩体类型 | 行为循环 |
| --- | --- |
| **矮墙**（0.4–1.1m） | `Crouch（完全看不见）` → 起身 `Stand`（1.0–1.6s 暴露窗口）→ 打一个点射（2–5 发）→ 伏低 `Crouch`（0.5–1.2s）→ 观察/换弹；被压制时只做 `PEEK_OVER`（露头 + 枪管，暴露面积更小） |
| **高墙 / 墙角** | `Crouch` 贴墙 → 侧向平移 0.45m 探身 `Peek`（0.35s 转出）→ 侧身射击（0.6–1.2s）→ 缩回（0.3s）→ 换弹/观察；可交替左/右探身（防止被预瞄） |
| **窗沿 / 二楼** | `PEEK_OVER` 从窗台探头 → 短点射 → 缩回（被打中的概率高，但视野与射界最好） |
| **战壕** | 壕内 `Crouch` 机动（敌视野外）→ 到达射击位 → 短暂 `Stand/PEEK_OVER` → 投弹或点射 → 缩回（"壕内转移"是战壕的核心价值） |
| **无掩体（被发现）** | 立即 `Prone`（0.4s）或 `Dive`（如果速度够）→ 盲射/压制 → 在班组掩护下寻找最近掩体（用掩体图跳过去）；**绝不原地站桩对射** |

- 探身/缩回有**最小/最大暴露时间**与**随机扰动**（`discipline` 属性）：老兵暴露时间更短、点射更精准；新兵可能暴露 2 秒还在乱扫。
- **预瞄**：从掩体后探身时，前 0.2–0.4s 是"转枪对准"阶段（此时不开火），这让玩家能看到"他正要开火"的节奏。

### 30.1.5 个性（Personality）参数

每个士兵生成时取一组相关随机值（受单位模板与经验影响）：

| 参数 | 范围 | 影响 |
| --- | --- | --- |
| `nerve`（胆量） | 0–1 | 被压制阈值、PINNED 恢复速度、是否敢捡手榴弹回掷、投降阈值 |
| `discipline`（纪律） | 0–1 | 暴露时间控制、是否遵守 ROE、是否在无命令时浪费弹药 |
| `aggression` | 0–1 | 前压意愿、是否主动换位到更激进（离敌更近）的掩体 |
| `initiative` | 0–1 | 无命令时的自主行动（自发给伤员包扎、主动搜刮弹药、主动追击溃兵） |
| `marksmanship` | 0–1 | 基础精度、射速控制 |
| `fitness` | 0–1 | 移动速度、翻越/扑倒成功率、肉搏胜率、失血速度 |
| `experience` | 新兵/老兵/精锐 | 上面所有参数的基准值 + 特殊能力（精锐会用烟雾、会识别 FPV 声音） |

阵亡会带走经验；补充的新兵参数更差 → 形成"老兵越打越金贵"的循环（也是伤员系统有意义的原因）。

### 30.1.6 士气与指挥链

`morale`（班组级 0..1，单位级受班组影响）：

```
morale_delta =
    - 0.35 * casualty_rate_recent(60s)        // 班内伤亡比例
    - 0.20 * avg_suppression(squad)
    - 0.15 * (ammo_state == RED or EMPTY)
    - 0.25 * (supply_starved)
    - 0.20 * (leader_down)                    // 班长倒下
    - 0.10 * (under_FPV_threat)
    + 0.15 * (kills_recent)
    + 0.20 * (friendly_artillery/armor_support)
    + 0.10 * (leader_within_15m && leader_alive)
```

| 等级 | 区间 | 表现 |
| --- | --- | --- |
| STEADY | 0.7–1.0 | 正常 |
| SHAKEN | 0.4–0.7 | 精度 -20%，前进迟缓，更依赖掩体 |
| WAVERING | 0.2–0.4 | 会自行后撤到最近的"安全"掩体，需要班长/玩家重整 |
| **BROKEN** | 0.0–0.2 | 溃散：丢下任务跑向最近的 FOB / 后方（可被班长或玩家"重整"，消耗 10–20 秒；失败则该单位退出战斗） |

- **班长（Squad Leader）**：位于班组中心 15m 内 → 全组士气恢复 +、压制衰减 +、命令延迟 -。班长倒下 → 副班长接替（2 秒），期间全组 `+0.2 suppression`，命令延迟 ×1.5。
- **士气是投降与倒戈的前置条件**（见 §40）。

## 30.3 战斗：弹道、命中、弹药

### 30.3.1 弹道

- 子弹是**实体**（不是 hitscan）：每个 tick 位移 `v * dt`，用**线段射线**（上一位置 → 新位置）做命中检测，因此 900 m/s 的步枪弹在 30Hz 下每 tick 走 30m 也能正确命中墙后的目标（不会穿墙）。
- 重力下坠（可选，默认开启但幅度小）：`9.8 m/s²`，只在 > 200m 时显著。
- 上限：同时活跃投射物 ≤ 4000（超出则最旧的转为"纯视觉曳光"）。

| 武器 | 弹速 m/s | 射速 | 伤害 | 穿透力 | 有效射程 |
| --- | --- | --- | --- | --- | --- |
| 突击步枪 | 900 | 600 rpm（点射为主） | 35 | 12 | 400 m |
| 班用机枪 | 850 | 750 rpm（长点射） | 40 | 16 | 800 m（压制 1000 m） |
| 狙击步枪 | 850 | 40 rpm | 75 | 24 | 900 m |
| 冲锋枪 | 400 | 800 rpm | 25 | 6 | 150 m |

| RPG-7 | 115 | 单发 | 破甲/杀爆 | 穿甲 300mm | 300 m |

### 30.3.2 命中判定（与掩体共用的关键一致性）

> **R3 重写**：原实现用汇总 `blocking < 1.0` 放行命中，只要有一点露头就能打中"整个人"，
> 包括被墙挡住的躯干。现在改为**逐命中点判定**。

```
// 步骤 1：选瞄准点（目标的一个暴露采样点，见 §20.1.3 表）
aim_point = target_select_point(target, shooter_skill, aimed_time)
            // 默认胸部；精锐/长时间瞄准偏向头部；被压制时随机偏移到任意点

// 步骤 2：加散布 → 得到实际弹道射线（§30.3.3 的误差锥）
ray = muzzle + dir(aim_point) rotated by spread(cone_rad)

// 步骤 3：求交（按优先级二选一）
   a) 若射线命中某个采样点 p（球体半径 = 该部位判定半径）：
        命中 ⟺ !ray_blocked(muzzle, p)        // 对【这一点】单独做遮挡测试
        命中部位 = p 对应的部位
   b) 若射线穿过身体胶囊但未命中任何采样点：
        取射线与胶囊的入射点 q，命中 ⟺ !ray_blocked(muzzle, q)
        命中部位 = 按入射高度插值到最近部位

// 步骤 4：结算
伤害 = weapon.damage * 部位系数 * 穿透衰减(若子弹先穿了掩体)
部位：头 2.6 / 胸 1.0 / 腹 0.85 / 四肢 0.45（四肢命中 → 出血 + 移动惩罚）
```

**一致性的精确表述**（这是支柱 P2 的技术保证，也是原文档里被过度承诺的那句话）：

| 判定 | 函数 | 粒度 |
| --- | --- | --- |
| AI"我暴露了吗" / 掩体评分 | `blocking_aggregate()` | **汇总**（加权比例，用于横向比较） |
| "我能看见他吗" | `∃p: !ray_blocked(eye, p)` | **逐点** |
| "我能打中他吗" | `!ray_blocked(muzzle, hit_point)` | **逐点，且就是被命中的那一点** |

> **看得见的那个部位，才是能被击中的部位。**
> 三者共用同一套采样点与同一个 `ray_blocked`（实现：`sim_core::ray::blocked`，见 §20.1.3 的命名对照），区别只在"汇总 vs 单点"——
> 汇总值只用于评分与探测速率，绝不作为命中门槛。

**验证（新增 B9，见 §90.3）**：把单位放在只露头胸、躯干被墙挡住的位置，
从正面射击 10 万次（含散布），断言：①命中全部落在暴露的部位；②被遮挡部位的命中率 ≤ 0.1%；
③同一位置的 `blocking_aggregate` 约为 0.7（证明汇总值与逐点判定确实不同，测试有意义）。

### 30.3.3 射击误差（"他们互相打不中"是特性）

```
cone_rad = weapon.base_cone
         * (1 + 0.9 * move_factor)          // 静止 0 / 走 0.5 / 跑 1.0 / 冲刺 1.6
         * posture_factor                   // Stand 1.0 / Crouch 0.75 / Prone 0.55 / Peek 0.95 / PeekOver 1.1
         * (1 + 1.5 * suppression)          // 压制影响巨大
         * (2 - 0.7 * marksmanship)         // 技能
         * (1 + 0.4 * distance_norm)        // 距离
         * (1 - 0.15 * aimed_time_norm)     // 持续瞄准同一目标的加成（0.3–1.2 秒，最多减 15%）
         * (1 + 0.8 * target_moving_factor)
```

- **目标选择效用**（打谁）：
  ```
  target_score = 0.35*(1/blocking_target)     // 越暴露越优先
               + 0.25*threat_level(武器、是否正对着自己、是否在瞄准自己)
               + 0.20*(1 - dist/effective_range)
               + 0.10*confidence(contact)
               + 0.10*objective_priority（比如正在拖走伤员的敌人、机枪手、RPG 手、无人机操作员优先级高）
  ```
  这就是"优先打机枪手 / 打担架队"的战术直觉来源（也引出医疗单位的受保护规则，见 §40.1.5）。

| 混凝土（200mm） | 22 | 600 | 30° | 剥落 → 钢筋裸露 → 破洞 |
| 沙袋 | 14 | 120 | — | 塌陷 |
| 钢板（薄/车辆） | 12 | 250 | 45° | 穿孔 |
| 均质装甲（坦克） | 装甲分区专用 | — | 60° | 见 §40 |
| 土方/战壕壁 | 18 | 300 | — | 塌方 |

```
穿透：power_left = weapon.pen - sum(material.pc * thickness_factor)
  power_left <= 0  → 子弹停止（在该点生成弹孔/火花），不造成伤害
  power_left >  0  → 继续飞行，伤害 × (0.55 + 0.45 * power_left/weapon.pen)（穿墙后伤害衰减）
 每次穿透额外增加散布（+40%/次）
```

- **破坏 = 掩体变化**：每次结构 HP 归零 → 修改柱 → chunk 标脏 → 掩体/导航/渲染局部重建（§20.1.7）。这就是为什么"越打越没掩体"是自然涌现的。
- **跳弹**：命中入射角（与法线）> 材质跳弹阈值 且 目标材质是金属/混凝土 → 生成反射射线（能量 ×0.45，散布 +25°），可造成跳弹杀伤（有专门的事件与音效）。

### 30.3.5 弹药经济（支柱 P4）

- **弹匣制**：`ammo = { 当前弹匣 n/N, 备用弹匣 m }`。换弹保留半空弹匣（放回备用，最后使用）。
- **携行量**（步枪手初值）：6 个弹匣（含枪上 1 个）；机枪手：1 个弹链箱（200 发）+ 1 个备用（100 发）；狙击：5 匣 ×5 发；手枪：2 匣。

| 状态 | 剩余比例 | 行为变化 |
| --- | --- | --- |
| GREEN | > 60% | 正常（允许长点射） |
| AMBER | 25–60% | 只打 3 发以内点射；`Suppress` 需要班组批准；优先精准射击 |
| RED | 5–25% | 单发；只在 `blocking_target < 0.5`（敌暴露）时开火；主动寻找弹药（尸体/弹药箱/FOB） |
| EMPTY | 0 | 不开火；撤退到补给点或捡枪；近距离转肉搏；士气惩罚 -0.15 |

- **阵地会沉寂**：一个班进入 RED/EMPTY 后，其火力输出在 30–60 秒内下降 60–80%，玩家能从声音上听出来。这是补给系统存在意义的表现层。
- **搜刮**：`Loot` 动作从尸体/弹药箱取弹匣（1.5–2.5s，需相对安全的姿态）。尸体被搜刮后标记（视觉上变了）。
- **FOB 补给**：站在 FOB 补给范围内 3 秒 → 补满（消耗 FOB 的补给储备，按弹匣计费）。

### 30.4.1 音频（关键玩法信号）

- 枪声：距离衰减 + 遮挡低通滤波（隔墙 → 闷响）；左右声像（俯视视角下方位判断很重要）。
- **FPV 无人机的嗡嗡声是玩法信号**：玩家听到 → 有时间反应 → 与 AI 同一套听感。
- 战斗 chatter：短促的喊话（与语音气泡同步），密度上限（避免噪声疲劳：同屏同时 ≤ 3 条语音）。
- 爆炸：近场低频 + 耳鸣效果（`Dazed` 状态时加耳鸣，1.5s）。
